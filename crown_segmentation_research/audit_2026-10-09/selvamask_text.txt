A.2. Annotation protocol
Software and setup. All annotations were performed using ArcGIS Pro. Annotators were provided with high-resolution
RGB orthomosaics and a predefined Area of Interest (AOI) layer to ensure consistent spatial coverage.

  1. Initialization: Load the site-specific orthomosaic and the Area of Interest (AOI) mask. Create a new polygon feature
     class for the session.
  2. Tracing Method: Use the Freehand Autocomplete tool to trace crown boundaries.
        • For isolated trees: Trace the full contour.
        • For clustered trees: Start the trace inside an existing neighbor’s polygon, trace the new crown’s outer edge, and
          end the trace back inside the neighbor’s polygon. The software automatically calculates the shared boundary to
          ensure zero overlap.
  3. Inclusion Criteria:
        • All visible canopy trees must be annotated.
        • Trees straddling the edge of the AOI must be included.

  4. Exclusion Criteria:
        • Do not annotate shadows, deep understory, or ambiguous blurry regions.
        • Delete any “sliver” or “gap” polygons accidentally created by the autocomplete tool in shadowed regions.

B.2. NMS parameters optimization for mRF1 metric
The mRF1 metric requires optimizing NMS and confidence thresholds on a validation set prior to benchmarking on the
test set (Baudchon et al., 2026). In this work, we optimize these hyperparameters for Detectree2 (Ball et al., 2023) on
the original Detectree2 dataset, and for all other methods on S ELVA M ASK . This ensures that Detectree2, our primary
baseline for tropical tree crown segmentation, remains strictly OOD relative to S ELVA M ASK during evaluation. The only
exception is for the QuebecTrees dataset in our OOD evaluation (Tab. 4), where the NMS is optimized on the validation set
of QuebecTrees itself for all methods due to the significant domain shift. For the rest of the methodology, i.e the grid search
setup, we follow (Baudchon et al., 2026).
